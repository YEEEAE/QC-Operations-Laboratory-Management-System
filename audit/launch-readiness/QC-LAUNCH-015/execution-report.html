Lifecycle semantics observed in source

  • APPROVED → APPLYING → APPLIED is executed in one database transaction. APPLYING is an intermediate state inside that transaction, not a separately durable in-progress job.
  • A persisted successful attempt is recorded with the owning-domain target version after mutation; exact-request replay requires persisted success evidence.
  • Some stale/invalid-transition failures can persist a FAILED attempt while the request remains APPROVED. The domain state APPLICATION_FAILED is defined but no current apply path transitions to it.
  • An audit failure should roll back the transaction and leave the request unapplied. Whether and when a separate failure-attempt row must persist, including failed-audit cases, remains NOT TESTED and needs an approved failure/retry policy.
  • A valid approval signature authorizes the change request decision; it is not evidence that target data was applied.

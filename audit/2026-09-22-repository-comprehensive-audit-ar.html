حدود ربط الدليل بالنسخة

صفحة صحة النظام تصرّح أن Release ID وBuild ID وGit SHA وMigration head كلها UNVERIFIED. لذلك لا يمكن الجزم أن النشر يعرض الكود عند 6c505e65…، ولا تُضاف نقاط طبقة التشغيل الرابعة إلى الدرجات.

هذه مشاهدة واجهة وخادم في لحظة واحدة، وليست E2E شاملًا أو فحصًا لسلامة سجلات المستخدمين. فراغ سجلات الاستلام والمختبر والوثائق لا يثبت نجاح إنشاء أو اعتماد أو إفراج أو توقيع.

الحالة READY هنا تعني اجتياز فحص التبعيات الأساسية المعروض. فشل تقارير الرفض يثبت أن جاهزية وظيفة مفردة تتطلب أيضًا تحقق مخططها ومسارها.

التوجه المقترح: «سجل الدليل»، بيئة عمل مختبرية تعطي كل سجل ومهمة وحالة وقرار مصدرًا واضحًا، وتتعامل مع كثافة البيانات كجزء من العمل اليومي. الهدف حضور بصري مميز ومتماسك، مع تركيب مختلف لكل مهمة: الاستلام ليس نسخة من المختبر، والمختبر ليس نسخة من الاعتماد أو التقارير.

هذا تصور تصميمي يحتاج اعتماد مالك المنتج وQC/QMS قبل تغيير المرجع الحالي. النظام الحالي يعتمد غرفة عمليات داكنة وخط Inter؛ استبدالهما قرار مقصود، وليس وصفًا لما نُفّذ. قرار المستخدم هنا يجعل واجهة النظام إنجليزية فقط؛ إشارات العربية وRTL في المواصفة القديمة تحتاج مصالحة خارج نطاق هذا التقرير. سلامة التفويض والقرارات وحالات السجل تتقدم على المظهر.

ثابت الظهور في التصميم الجديد

كل حساب نشط ومسجل دخوله يرى مجموعات وصفحات العمل العادية، بما فيها روابط الإدارة وبقية مجموعة System الظاهرة في الصور. اختلاف الدور يغيّر الأفعال والبيانات الإدارية المصرح بها داخل الصفحة، ولا يخفي خريطة النظام. الاستثناء الوحيد هو صفحتا /system/health و/system/control-center؛ لا تظهران ولا تفتحان بالرابط المباشر إلا لحساب yazeed النشط ذي دور SYSTEM_OWNER.

واجهة النظام إنجليزية فقط. اختر خطًا لاتينيًا مقروءًا ومرخصًا بدل Inter، مع أرقام جدولية للقياسات والمعرفات. اجعل العناوين والأفعال قصيرة وطبيعية، والتفاصيل الطويلة عند الحاجة فقط. عرّف شبكة ومسافات وحدودًا ورموزًا أصيلة، وألوان حالات لا تعتمد على اللون وحده. الحقول والجداول والتنبيهات والطباعة تملك حالات تحميل وفراغ وخطأ وتعارض وحفظ غير مكتمل.

تجربة قابلة للتشغيل

اختبر النصوص الفعلية بالإنجليزية واتجاه LTR، ولوحة المفاتيح والتركيز وقارئ الشاشة والتكبير 200% وعرض 320px وتقليل الحركة. اعرض منع الصلاحية منفصلًا عن عدم توفر الخدمة أو عدم وجود سجلات. أثبت الأداء بزمن المهمة وكثافة الصفوف قبل/بعد، ولا تغيّر منطق الخادم أو سجل التدقيق من أجل العرض.

ضوابط الإبداع قبل التجربة

  • لا تدرجات صارخة أو تلوين قوس قزح أو نيون أو باستيل عام أو أسود مع بنفسجي جاهز.
  • لا خلفية بيضاء نقية، ولا زجاج سائل أو كرات شعاعية أو شبكات نقطية زخرفية أو ظلال إسقاط تجميلية.
  • لا نسخ أيقونات Lucide كهوية، ولا نجوم Sparkle أو إيموجي أو أسهم متحركة أو حركة Hover للزينة.
  • لا بطاقات ميزات ثلاثية أو Bento متكرر أو نافذة Terminal للزينة أو زوايا لينة متشابهة أو شريط جانبي ملون متكرر.
  • لا Inter أو Geist أو Space Grotesk في الاتجاه الجديد إلا قرار موثق يلغي هذا الشرط.
  • لا شهادات مستخدمين أو عروض منتج وهمية أو خطط أسعار شكلية أو لغة تسويقية من نمط «ليس X بل Y» أو تعداد بعلامات صح زخرفية أو شرطة مطولة أسلوبية.
  • لا فقرات تفسيرية تملأ الشاشة، ولا عبارات إنجليزية عامة تبدو مولدة آليًا؛ اكتب تسمية وفعلًا ورسالة تعافٍ بصوت موظف QC، واكشف الشرح التفصيلي عند طلبه.
  • اعرض بيانات منتج حقيقية أو اصطناعية موسومة، وحالات Skeleton مطابقة للبنية عند انتظار البيانات. لا تنشئ سياسة خصوصية أو شروط استخدام بصياغة متخيلة؛ اطلب نصًا معتمدًا ومالكًا عند الحاجة.

هذه ضوابط ضد القوالب البصرية الجاهزة، وليست حظرًا لظل أو حركة أو رمز له وظيفة واضحة ومثبتة باختبار استخدام. معايير القبول التصميمية مذكورة في البرومبتات P03–P12 من ملف التنفيذ.

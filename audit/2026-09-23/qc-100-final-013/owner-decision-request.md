# QC-100-FINAL-013 — طلب قرار مصدر التفتيش والحكم عليه

**الحالة:** مسودة لملاك QC/QMS وضبط الوثائق؛ غير معتمدة ولا تخوّل التنفيذ.

**القرارات المطلوبة:** PD-01 وPD-02 وPD-07 في `Documents/DECISION-ASSUMPTION-REGISTER-026.md`.
**المتطلبات المرتبطة:** REQ-INSP-004 وREQ-INSP-006 وREQ-WFLOW-004 وREQ-WFLOW-014.
**عقد سير العمل:** TR-INSP-001..006B في `Documents/STATE-MACHINES.md`.

يُستكمل هذا النموذج من مصادر مضبوطة ومعتمدة، مع إرفاق المصدر وإثبات هويته المضبوطة. لا تُستنتج الحقول الناقصة من كود التطبيق أو بيانات الاختبار أو الأمثلة أو السجلات التاريخية. إذا لم ينطبق حقل، يُذكر «لا ينطبق» مع مبرر المالك؛ ولا تُترك القرارات العلمية أو قرارات الصلاحية المطلوبة ضمنية.

## ضوابط معتمدة يمكن تطبيقها الآن

تثبت الوثائق الحالية الضوابط التالية، ويمكن تطبيقها دون اختيار حدود علمية أو اعتبار قرارات PD المفتوحة محسومة:

- التقرير المضبوط ينشأ من إصدار قالب تفتيش معتمد، ويحفظ إصدار القالب وسياقه ومصدر القبول وبصمة المصدر عند توفرها (BR-INSP-001..003).
- بيانات النتيجة المشاهدة تأتي من المستخدم أو أداة/مصدر تقني معتمد؛ لا يحل الذكاء الاصطناعي محل النتيجة الرسمية (BR-INSP-005 وREQ-INSP-016).
- المتصفح لا يقرر PASS/FAIL. يحسب الخادم النتيجة حتميًا فقط من قاعدة قبول معتمدة ومربوطة بمصدرها (BR-INSP-006 وREQ-INSP-006). أي قيمة أو قاعدة علمية غير موجودة في مصدر مضبوط لا تُخترع.
- مصدر القبول المفقود أو غير الفعّال أو المنحرف يمنع التقييم؛ تبقى النقاط غير القابلة للتقييم بلا نتيجة رسمية (PD-01/02 وREQ-INSP-004).
- نقاط التفتيش الإلزامية تكتمل قبل الإرسال، والسياق المضبوط يتجمد عند الإرسال، وتغييرات المراجع تمر عبر مسار إعادة مضبوط (BR-INSP-008/010/011).
- فصل المراحل المعتمد يبقى: المراجع يبدأ المراجعة، معتمد المرحلة الأولى يسجل حدث اعتماد دون توقيع، ومعتمد QCM النهائي يوقّع بعد إعادة التحقق؛ النسخة وSoD والتدقيق والمعاملة الذرية حراسات مستقلة (TR-INSP-003/006/006B وP-05).

هذه الضوابط لا تغلق PD-01 أو PD-02 أو PD-07: الوثائق لا تتضمن الحدود لكل نقطة، أو مرجعًا مضبوطًا وبصمة لمصدر فعلي مربوط بالقالب، أو إجراءً معتمدًا يحدد هل يُسمح بالحكم اليدوي ومن يملكه. لذلك تظل النتيجة الرسمية والمسار الإيجابي محجوبين حتى تكتمل مدخلات المالك.

## د. النتيجة وتبعات سير العمل

| الحقل | إجابة المالك |
|---|---|
| النتائج الرسمية للتقرير وتعريفها الدقيق، بما فيها HOLD إن انطبق | |
| طريقة تجميع نتائج النقاط إلى نتيجة التقرير وبند المصدر | |
| الإجراء عند وجود نقاط ناقصة أو متعارضة أو يتعذر تقييمها | |
| الأدلة المطلوبة قبل SUBMITTED | |
| التبعة على سجل الاستلام بعد الاعتماد النهائي؛ مع تأكيد أن الإفراج إجراء مستقل | |
| تبعات FAIL/HOLD أو سلوك إنشاء NCR ومصدره ومالكه؛ لا سلوك آلي ما لم يُعتمد صراحة | |

تسلسل الاعتماد الموثق حاليًا هو `DRAFT → SUBMITTED → UNDER_REVIEW → PENDING_QCM_APPROVAL → APPROVED`. لا يُقترح تغييره إلا إذا تعارض معه قرار مضبوط مقصود؛ وعندها يلزم تحديد معرّفات الانتقال البديلة والأدوار والصلاحيات والنطاق وحالات الرفض. فيما عدا ذلك، يوفّر هذا القرار مدخلات المصدر والنتيجة الناقصة ويُبقي التسلسل المعتمد كما هو.

## هـ. أمثلة القبول المطلوبة من المالك

أرفقوا أمثلة مستندة إلى المصدر تشمل:

1. كل نوع قاعدة وحدودها الدقيقة كما تُستخدم في الطريقة المعتمدة.
2. غياب المصدر أو عدم اعتماده، واختلاف الإصدار أو البصمة، وانحراف المصدر.
3. حالات السماح بالحكم اليدوي ومنعه، بما فيها الموقّع غير المخوّل وتعارض المنشئ/المنفذ.
4. النقاط أو الأدلة الناقصة، والنتائج المتعارضة، والقياسات التي يتعذر تقييمها.
5. كل نتيجة رسمية وتبعتها على سجل الاستلام.
6. فصل الأدوار بين المنشئ/المنفذ والمراجع ومعتمد المرحلة الأولى ومعتمد QCM النهائي، مع التركيبات المرفوضة.
7. الإصدار القديم والطلب المكرر ومحاولات الاعتماد المتزامنة؛ يفوز طلب واحد فقط ولا تخلّف حالات الرفض أي آثار جانبية.

لكل مثال، اذكروا: معرّف الحالة، بند المصدر المضبوط، المدخلات والسياق، القرار المتوقع أو فئة الرفض الدقيقة، الحالة/الإصدار المتوقع، متطلبات التوقيع والتدقيق، وتأكيد عدم حدوث أثر على الاستلام أو الإفراج عند الرفض.

## و. مخرجات المالك اللازمة لرفع الحظر

أعيدوا جميع ما يلي:

- هذا النموذج مكتملًا ومعتمدًا، مع أسماء الملاك وإثبات الاعتماد.
- مصدر الوثيقة المضبوط وإصداره المعتمد ونطاق سريانه وسجل مستودعه وبصمة محتواه.
- ربطًا كاملًا لمعايير نقاط التفتيش/المعامل، ومراجع الدقة أو التقريب التي تنطبق فعلًا.
- قرار الحكم اليدوي الصريح، وموقّعه وصلاحيته ونطاقه وقواعد الفصل بين المهام والأدلة والتدقيق.
- أمثلة القبول والرفض المستندة إلى المصدر في القسم هـ.
- أي تغييرات معتمدة على الأدوار أو الصلاحيات أو انتقالات الحالة أو حقول البيانات أو مدد الاحتفاظ، موضحة كلٌ بمصدرها ومالكها. مدد الاحتفاظ يحددها المالك ولا يقترح هذا النموذج أي مدة.

**بوابة التنفيذ:** إلى أن تُعتمد هذه المخرجات ويُوفّق بينها وبين وثائق التتبع وآلة الحالات، يبقى تقييم النتيجة الرسمية ومسار الاعتماد الإيجابي محجوبين. إجراءات إنشاء التفتيش من الاستلام والمراجعة واعتماد المرحلة الأولى والتوقيع النهائي الموجودة تظل خاضعة لحراسات الخادم. لا تستخدموا نتيجة `PASS` مزروعة في اختبار بوصفها دليلًا على أن التطبيق يستطيع إصدار نتيجة رسمية.

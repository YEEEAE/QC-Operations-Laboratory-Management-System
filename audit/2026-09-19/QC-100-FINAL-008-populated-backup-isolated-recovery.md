A second restore into the populated target returned `RESTORE_TARGET_NOT_EMPTY` and did not mutate its rows.

The restore executor now requires a source database name, accepts only loopback PostgreSQL URLs and explicitly named `qc_restore` targets, rejects source/target equality and password-bearing target URLs, checks the target is empty, fully decodes the archive before connecting, and restores without `--clean`. Recovery manifest checks now accept and verify the migration filename used by release identity; PostgreSQL version validation accepts the server’s version string with its distribution suffix.

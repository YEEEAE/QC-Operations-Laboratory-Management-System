# QC-ADP26-15 — Notifications read state and paging handoff

## Changed

- `/notifications` now uses the existing authenticated `pageAccessDecision` route and `PERM-NOT-VIEW-OWN` read use case, with All/Unread filters, a visible bounded page label, 50 rows per page, exact filtered total, and previous/next navigation.
- Added `notifications.markOwnRead` Astro Action. It accepts a notification ID only, resolves the actor from the authenticated server context, and calls `NotificationService.markOwnRead`; recipient ownership, active-account state, and `PERM-NOT-MARK-READ` remain enforced by the use case. The action is monotonic/idempotent and does not grant `yazeed` a bypass.
- The standalone read control is separate from the record destination link. Duplicate client submissions are suppressed; native form posting remains available. A confirmed result returns to the same filter/page. Missing-or-other-recipient, permission denial, provider failure, stale (not expected for this versionless operation), and unknown write outcome have separate recovery copy. The notification title remains visible as the human reference; no UUID is used as a heading.
- Dashboard unread count now uses the full authorized total while its attention queue uses only the newest bounded 50-row sample.

## Read/write, transaction, and policy boundary

- Read: recipient-scoped `qc.notifications` rows, optionally `read_at IS NULL`, ordered by `created_at DESC, id DESC`; exact count and bounded page are read in one `REPEATABLE READ, READ ONLY` transaction. Page size is clamped to 50 and the requested page to the available range.
- Write: one guarded update to `qc.notifications.read_at`, matching both `id` and authenticated `recipient_user_id` and only when `read_at IS NULL`; a scoped read returns the existing state for replay and hides other recipients' rows. No expected version exists for this monotonic preference state, so stale-version checking is N/A by contract.
- No schema migration was needed. No business row, controlled record, audit event, or outbox event is written. This is a user notification read-state change, not business completion or approval. The finding's open owner decision on whether notification preferences require a separate audit policy remains open; no audit or outbox contract was invented.

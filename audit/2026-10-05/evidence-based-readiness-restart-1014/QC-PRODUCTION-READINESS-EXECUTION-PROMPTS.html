قواعد التنفيذ

  • أصلح السبب المصدرّي فقط عند وجود عيب مثبت؛ لا تصلح NOT VERIFIED على أنها bug.
  • كل وظيفة scientific/document approval تظل fail-closed حتى تزويد واعتماد المصدر/القرار.
  • كل بطاقة تحمل ID فريدًا وتعريفًا ومصدرًا وcriteria وverification/stop conditions.
  • فشل test/CI يحقق السبب قبل التصحيح؛ تعذر log ليس سببًا معروفًا.
  • لا تعتبر نتائج tests على unclean checkout release evidence. لا commit/push/deploy ضمن هذا الـplaybook.

ترتيب الدفعات حسب الاعتماد

    كل Prompt

    FINAL-PRODUCTION-READINESS-RECONCILIATION

    هذا التوجيه تدقيق فقط؛ لا يُجري إصلاحًا ولا يرقّي نتائج قديمة. ثبّت SHA/dirty fingerprint جديدًا، أعد جمع كل 88 بندًا من الصفر على الحالة النهائية، نفّذ suites الآمنة المحددة مع exit/timestamp، اربط exact CI run والـartifact، تحقّق من schema/runtime عبر قناة read-only مصرح بها، اجمع نتائج integration/runtime/Human UAT/restore/AI/performance فقط عند وجود التفويض والسياسات، واحسب 27 scorecard آليًا من ledger ثابت مع validation يمنع التكرار/تغيير المقام/PASS بلا evidence/N/A بلا applicability. قارن Before/After مع source/runner/test/environment binding. افحص جميع P0 mandatory والـopen risks. عند نقص أي بوابة إلزامية أصدر NO-GO أو BLOCKED؛ لا تحول BLOCKED/NOT VERIFIED إلى PASS ولا تصدر readiness بالمتوسط.

    قبول هذا البرومبت: تقرير reconciliation كامل، IDs والـdenominators كما هي، source refs، timestamps، environment، SHA، command/exit، PASS/FAIL/BLOCKED/NOT VERIFIED مفصولة، GO/NO-GO مع gate-by-gate rationale. لا يعدل ملفات المنتج أو قواعد البيانات.

# Inspection draft save contract

Derived implementation contract for QC-ADP26-03; the permission and workflow sources remain [PERMISSION-MATRIX.md](PERMISSION-MATRIX.md), [STATE-MACHINES.md](STATE-MACHINES.md), and `src/shared/authorization/policy-registry.ts`.

The results Action authenticates the server-resolved actor. Before evaluating or persisting results, `RecordInspectionResultsUseCase` authorizes `PERM-INSP-EDIT-DRAFT` / `EDIT` on the existing report, its owner/assignee scope, DRAFT state and expected version. Read visibility does not grant edit authority. Named yazeed has no state/version bypass. Draft editing has no approval/SoD/reauthentication/signature ceremony in the registered EDIT policy; approval ceremonies remain separate.

`PostgresInspectionRepository.saveDraft` locks the report with `SELECT FOR UPDATE`, repeats the same authorization against the locked owner/assignee/state/version, then updates the aggregate version, replaces result rows and appends the existing `MEASUREMENT_RECORDED` audit action (`kind: INSPECTION_RESULTS`) in one transaction. Audit is mandatory even when no audit adapter was supplied. The PostgreSQL audit adapter is rebound to that transaction. Audit payload records only result count and old/new versions; values and free-text observations remain in result storage. An audit insert failure rolls back the report and results. A same-version concurrent save has one winner; stale replay is rejected without another edit/audit.

Reads: report and its frozen receiving/template/criteria/results context; server criteria for the bound template version. Writes: report updated metadata/version, result replacement, audit. Existing result IDs, report/point/user foreign keys and unique constraints remain enforced. No schema change is needed. This DRAFT save has no registered downstream outbox consumer, receiving transition, final-result aggregation or signature effect; outbox remains unchanged. Submit/approval/release effects belong to their separate workflows. No synthetic notification or approval event is introduced.

The execute workspace projects frozen `criteria_snapshot` into its template read context. Numeric readings travel as decimal strings from the input through the Action and domain; the use case validates plain decimal notation and tags only server-resolved numeric points for the repository. PostgreSQL stores them in the existing unconstrained `NUMERIC` column and the DB driver/type contract returns a string. Exact-decimal evaluation compares those strings against approved frozen criteria; absence of a formal rule leaves the official result unset. No precision, scale, tolerance, or rounding rule is introduced.

Every saved point value and point-level `remarks` use the existing `inspection_report_results` row. The existing one-value constraint requires a typed value for every row: `REMARK_ONLY` stores its text observation and server-resolves `REMARK`; `NOT_APPLICABLE` stores the canonical text `N/A` and server-resolves `NA`. Required points are validated against the frozen server-side criteria before replacement, and remarks without a value are rejected rather than reported as saved. The execution form has no general `notes` persistence field: general notes are not collected or submitted, and the page states that they are not saved. No schema widening, new outbox event, or new audit payload content is introduced.

Controls use the registered permission/scope/state decision. Versions cross JSON as strings and are coerced to bigint on the server. Pending submission is guarded; rejection preserves entered values and focuses the status region. Errors transport canonical codes through the common Astro error mapping. A transport interruption does not prove rollback: compare current results/history before retrying. PostgreSQL numeric/remarks/NA roundtrip, source-hash binding, native POST, unavailable-source classification, 200% zoom, manual AT and human UAT remain separate open acceptance items.

Implementation contract, 2026-10-06. Local implementation and technical verification do not approve the transcriptions or authorize production migration.

The XLSX master governs identities, exact official titles, revisions and order. `master-rev14.json` contains 194 nonblank entries, SHA-256 `199f1a8c453e4340fdf3e0c79ba93c53510f35b4b2b5875f6ef8e55750f128e4`. Official spelling and trailing spaces are preserved; search normalization never changes the title. `extract-master.py --check` validates the original XLSX and fails on any source correction rather than rewriting the baseline.

Migration `0046_inspection_report_catalog` is additive. It registers the complete master and leaves historical templates/reports unchanged. Existing unlinked templates remain historical and cannot originate new inspections. No item mapping is manufactured. Identity fields and source evidence are immutable; a master correction requires a reviewed forward migration. Source status can change only through controlled application/migration work with audit evidence.

The page inventory in `source-evidence.json` represents the 28 pages actually available in `inspection-repr.pdf`, with document/page/image digests. Cropped/unreadable pages remain unresolved even when another clear page of the same identity exists.

`ImportControlledInspectionSourcesUseCase` verifies the full immutable catalogue, serializes import, retains source evidence and creates 13 source-bound DRAFT templates. Identical imports are idempotent; different content for the same report revision fails rather than overwriting it. A pre-existing empty DRAFT of the same exact identity/revision may be bound with an audited version increment. Approved content, sections and points cannot be edited in place. Imported drafts require transcription review and the existing P-06 authenticated E-Signature approval; import creates no approval or mapping. Catalogue identity authoring also starts DRAFT until its source content is bound. This prerequisite does not change the authorized approval role set or signing ceremony.

Creation accepts stable catalogue identity only. Receiving execution resolves active effective item-code mappings to current APPROVED digital versions with matched source evidence and catalogue revision. Unique candidates auto-resolve; ambiguity requires explicit selection from that candidate set. Missing mappings and configured-but-unapproved templates fail closed. There is no description-based or General Products fallback. Mapping creation requires the existing explicit template-administration permission. Distinct mappings remain distinct candidates; an identical active pair is idempotent. Reusing a stopped pair requires an explicit correction path, not silent reactivation.

The database repeats origin checks at INSERT, locks the receiving/version/catalogue and serializes item-mapping access. It rejects an unmapped, unapproved, outdated, nonmember or unresolved source and duplicate in-flight reports. The repository resolves receiving and template identity itself and captures exact schema, allowed values, requirements, units, sections and headers in the immutable CREATION snapshot. Historical reads use the captured receiving/schema context even after source state changes.

Digital schemas cover fixed point observations, controlled options, exact text/integer/decimal/measurement values, boolean Yes/No, remarks, read-only requirements and repeatable child rows. Blood Line Parts uses component rows; Syringes and Feeding Bottle retain equipment/accuracy/standard-reading/equipment-reading/result tables. Empty critical-point columns remain null source designations. General Products, Liquid Chemicals, Hypodermic Needle and Packaging Film layouts remain source-blocked; White Label requires an available readable source. The engine can represent their data types but no controlled contents are invented.

Native POST supports digital draft saving, adding repeatable rows and submitting saved data. Unknown/read-only/duplicate controls are rejected; numbers remain exact strings. Complete submission requires each required observation/result, sampling facts, required table cells and disposition. General remarks are saved in `form_values`. Observed PASS/FAIL is an inspector assertion, not an official scientific aggregation. REMARK requires remarks. Disposition never changes `final_result` or releases Receiving. The existing scientific-result source/aggregation blocker remains open.

AQL remains controlled manual input with the existing reference requirement, authorization, version check and audit transaction; no sampling table is invented. Equipment selection resolves current calibration and snapshots on the server, checks existing assets eligibility and scope, and records a versioned audited link. Client certificate/snapshot claims are not trusted. Measurement metadata must reference a captured link. SUBMISSION captures form observations, AQL and equipment evidence in its immutable snapshot. Completed form values cannot be silently overwritten; return/resume/reopen follow existing audited state transitions. Supervisor and QCM approvals keep their existing separate signatures and permissions; PASS is never Receiving release.

Administration provides bounded 50-row server search and accessible native selection by exact Doc. Code/title/revision, source state, digital lifecycle and item mapping count. Source preview lets authorities review transcribed content before approval. Historical execution/detail/review render the frozen schema, not current catalogue contents.

Verification and outstanding source/implementation/evidence gaps are recorded in `audit/QUARANTINE-INSPECTION-REPORT-MIGRATION-REPORT.html` and the machine-readable conflict artifact. Neither this document nor engineering fixture signatures are human QC acceptance.
